# CLAUDE.md: agent briefing for tabletop-craft-ar

Read this, then `README.md` (short, visual), `docs/OVERVIEW.md` (features, status, versions), `docs/KNOWN_ISSUES.md`, `docs/PROTOCOL.md` (normative), `docs/ARCHITECTURE.md`, `docs/TESTING.md` and `docs/QUEST_SETUP.md`. `docs/PLAN.md` has the phases and `docs/RESEARCH.md` the sources.

## What this is
A Paper plugin streams a box of blocks, player positions and block changes over a JSON WebSocket to a Quest 3 Unity passthrough app, which renders it as a table-top miniature. The Quest sends head and hand poses back at about 30 Hz, and the plugin drives a giant avatar (Mannequin with the SCALE attribute + two ItemDisplay hands) that Java players see. The Quest has no game account and never speaks the game protocol.

## Protocol rules
- **Versioning (from 1.0.0, semantic):**
  - One version for plugin `version` (build.gradle.kts), the app's `bundleVersion` and the PROTOCOL.md version line, all from `VERSION`.
  - Patch (1.0.x) for fixes, minor (1.x.0) for new features that old plugins/apps can ignore (new optional fields, new messages behind caps), major (2.0.0) for anything that breaks a plugin/app of the same major version. Every protocol change gets a changelog entry.
  - Before 1.0 there was no backwards compatibility (0.X versions just had to match).
- **Releases:** one `VERSION` file at the repo root is the single source: Gradle reads it for the plugin, and `TabletopBatch.BuildApk` sets the app's `bundleVersion` and versionCode from it. To release a feature set:
  1. bump `VERSION` (0.X.0; patch for fixes);
  2. update the PROTOCOL.md header and its changelog;
  3. commit `release: v0.X.0`;
  4. tag `v0.X.0`;
  5. `gh release create v0.X.0` with notes (what's new, what was verified on the headset, known gaps), attaching the plugin jar, the APK and the server starter zip.
  6. Build the store APK with `TabletopBatch.BuildReleaseApk` (release key from the `TABLETOP_KEYSTORE*` variables, never in the repo) and upload it to the BETA channel with `tools/release/upload_quest.sh` (docs/RELEASING.md).
  Never attach the client jar, pack.zip, entity_models.json, sounds.zip or a keystore.
- `docs/PROTOCOL.md` is the contract for the plugin, Quest app and tools. Golden examples are in `tools/fixtures/`; Java (`FixtureTest`) and Python tests read them.
- Frames: tabletop frame is right-handed, metres, axes parallel to the world, origin at the region's local (0,0,0) corner. Unity conversion is `p=[ux,uy,-uz]`, `q=[-qx,-qy,qz,qw]` (PoseSender/TabletopPose). Mesh vertices are mirrored on Z and triangles re-wound in TabletopRenderer.
- Known gaps vs the spec are listed in `docs/TESTING.md` under "Spec deviations".

## How to debug
- Server: `/tabletop status`, `/tabletop avatar status` (logs `AVATAR_STATE` / `AVATAR_ENTITY`). Set `debug.avatar-state: true` to stream entity positions to clients.
- Quest: `adb logcat -s Unity | grep Tabletop`. The block menu's Info tab (left ≡) shows LINK, RTT, WORLD, PACK, TABLE and POSES; `"show_hud": true` in tabletop.json (or Show HUD in the Info tab) brings back a small head-locked copy.
